# 账户作战统计

作战统计继续始终在客户端采集，不需要开启面板。战斗内仍默认查看自己的当前战斗，
按原口径统计有效伤害（物理／法术／真实／元素）和有效治疗，同名干员合并、召唤物归属原干员。
统计读取不改变模拟、逻辑帧、战斗结果或联网结果协议。

## 保存与完整性

- 服务端在实际创建战场时登记 battleId、回合、战场、参与者和内容身份，战斗结束登记最终时间；
  清单随同版本检查点及结算 outbox 保存，与回放录制、大小预算及保留额度独立。
- 客户端在战斗完成或清理时保存快照，只将本人的干员行加入账户绑定的本机重试队列。
  对局结算后上传；结算尚未写入时保留重试，不影响准备就绪、战斗上报或结算本身。
- 服务端校验账户参赛归属、战场、回合、规则身份、数据长度和有限非负数值，拒绝队友行、虚构战场、
  超时数据及伤害类型合计不一致的记录。同战场幂等保存，不累加；完整记录优先，其次保留较长采集。
- `complete` 同时要求客户端确实完成模拟、采集时长与服务器最终时间吻合。页面关闭、模拟失败、
  战场切换后未跑完等情况可能留下部分记录。缺失战场不当作零伤害，接口返回预期／已记录／完整数量。
- 这是**客户端采集的个人复盘数据**，并非防作弊排名凭据；服务端校验不证明客户端没有篡改伤害数值。

SQLite 独立 `combat_schema=1`，`combat_matches` 保存本人战场清单，`combat_records` 保存 gzip 汇总附件，
关联现有 `(game_id,user_id)` 结算。原账户 schema、回放格式及结算 payload 不改；新增表随原用户卷备份。
附件随对局记录长期保留，回放淘汰不删除它们。名单最多每人每局 128 个战场，单快照最多 128 行、
64 KiB 原始 JSON；每人每局汇总附件原始 JSON 总预算 512 KiB，实际入库压缩。名单截断会明确维持部分状态。

本机重试队列为 `sp.combat-outbox.v1`，按账户／对局／战场去重，最多 10 场、2 MiB、7 天；
每轮至多发送 8 个附件，15 秒轮询，失败延迟重试。换号不上传旧账户数据，无可用 localStorage 时保留内存队列。
预算或保留期外的最旧待上传数据可被清理，服务器完整性仍会指出缺失；最新一局的原本机缓存也继续保留。

## 历史界面与旧数据

博士档案 → 对局记录 → 详情 → 作战统计，按需读取服务器附件；即使没有本机缓存，也能跨设备查看逐回合／本局累计。
服务器记录优先，本机数据可补充缺失或较短的部分记录，同战场不重复累加。沿用原面板位置、按钮、颜色、
回合翻页和 Esc 关闭顺序，明确标注完整／部分／本机来源，未记录显示破折号，合法完整的零值仍为零。
短横屏历史面板避让统一顶栏，数值保留至少 12px 的可读字号。

有可靠 matchId 的最新本机缓存会尝试补传；缺少 UUID 的旧缓存仅在原有私有回放确认 combatHistoryKey 后使用。
旧对局的战场清单可以从本人仍保留的回放中恢复，旧缓存无法证明完整时按部分记录保存。
没有缓存的旧明细不会从结算总伤害编造；本版不自动重模拟历史回放，因为规则版本和共享领袖血池事件也需要正确复现。

统计附件仅有本人私有接口。公开档案／公开回放原授权范围不扩张，也不会因开放战绩而自动公开此附件。
`profile:pull` 的本机调试快照同时复制本人已入库的战场清单和统计，不包含其他账户附件；旧生产库缺少新表也可只读导出。

## HTTP

| 方法 | 路径 | 内容 |
| --- | --- | --- |
| GET | `/api/user/combat?matchId=<id>` | 本人 `{combat:{v,source,playerId,fields,records,coverage}}`；未参与为 404 |
| POST | `/api/user/combat` | `{matchId,record:{v:1,battleId,round,fieldId,cs,seconds,complete,rows}}` |

每行包含 `key/ownerId/defId/name/kind/damage/healing/types`；DPS／HPS 按保存的战斗时间派生。
POST 使用已有 Cookie、同源 JSON 检查及限流，只有该路径允许最多 66000 字节，其余账户操作仍为 8192 字节。
数据不进入历史列表响应、`b.progress` 或 `b.result`。HTTP／SQLite 失败不记录凭据、恢复码或上传原文。

`test/users/profile-debug.test.js` 验证私有调试副本。

验证服务器统计及 1920×1080／844×390 截图；`test/ui/archive-details.e2e.test.js` 保留旧缓存和详情布局覆盖。
