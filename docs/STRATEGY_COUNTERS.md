# 策略经营计数

右侧策略图标左侧、悬浮说明及「本局信息」共用计数展示。仅呈现当前玩家（或侦察对象）的服务器状态，不在客户端另建计数。

| 策略 | 计数 | 结束或恢复 |
| --- | --- | --- |
| 潘格尼尼 | 累计消费 `n / 55` | 奖励实际获得后显示「已完成」；达到门槛但授予失败时仍标注未获得 |
| 绮良 | 本次消费循环 `n / 20` | 沿用原消费计数的余数，跨回合保留 |
| 贾维 | 刷新 `n / 6`，回合奖励 `n / 2` | 奖励上限时图标旁显示「本回合已满」 |
| 杜遥夜 | 本回合特殊刷新已用 `n / 2` | 用尽显示「本回合已用尽」，下回合恢复；每次保底干员数量不作为次数上限 |
| 玛恩纳 | 下回合追加资金 `n / 3` | 本回合收益达到上限后显示「本回合已满」 |
| 巫恋 | 本回合已交换 `n / 1` | 仅成功交换消耗次数；出售精锐不消耗，下回合恢复 |
| 休露丝 | 本回合已用优惠 `n / 1` | 仅购买对应盟约干员消耗，下回合恢复 |
| 佩佩 | 待用特殊刷新「剩余 n 次」 | 升级奖励可累积，主动刷新时消耗，不标成固定容量或免费刷新 |

阈值优先读取具体策略 buff 的黑板；杜遥夜的前两次和休露丝的首次沿用规则实现的固定限制。
`server/match/bandProgress.js` 从既有 counters／round 派生视图；回合计数须检查原 `:r`，读取视图不得触发惰性归零。
视图使用原 `effectsView` 和可选 `PlayerBattleInput.bandProgress`，后者仅供战斗观战保留经营期的状态；不修改规则、逻辑帧或持久化计数格式。
客户端 `ui/strategyProgress.js` 按 progressType 区分消费、次数、收入和待用次数，共用中英文文案。

本轮按用户要求仅处理经营阶段。埃芒加德的战斗复活、大帝／卡莱莎等每干员叠层未改动；按回合固定发放的策略继续使用原说明及回合信息。

验证：`band-progress.test.js`、原策略回归、`strategy-progress.test.js`、`spectate-effects.test.js`，以及 Chrome／Firefox 的 `strategy-progress.e2e.test.js` 和原贾维截图回归。
