### 37.11 Waiting-room ready feedback for every room member (PR #887, @YinqiMargatroid)

- **Reported (2026-10-25):** clicking 准备就绪 in a co-op waiting room is silent for both the sender and teammates;
  it should use the briefing's ready sound for everyone in the room.
- **Cause:** the room sends `room.ready` directly without a sound, while `g.infoReady` uses the local action's
  `ready` success cue. There was no listener for ready transitions in the public waiting-room state.
- **Change:** `installAudio` observes an existing human seat changing from unready to ready in a live, same-room
  waiting-room update and plays `sfx.ui.ready` on each client, including the sender and spectators. Snapshot replay,
  restoration, cancellation, seat replacement/AI additions and match lifecycle changes stay silent. Local audio
  settings and browser unlock remain in effect. Cancelling and readying again retriggers the cue with no time-based
  cooldown. No new network frames, translations, game data or sim changes.
- **Evidence / [ASSUMED]:** this shared-room playback policy follows the reporter's request; no official multiplayer
  recording was independently checked. The sound itself reuses the existing briefing `g.infoReady` manifest key.
- **Regression coverage:** room-state subscription tests cover all listeners, repeat/cancel/re-ready, snapshots,
  reconnect restoration, AI/seat changes and match/solo exclusions. A real-server browser test checks shared playback
  and the briefing sound through actual decoded Web Audio sources.

### 37.48 同一名干员的两件相同装备都生效（#902，round58，Claude）

玩家报告（#902）：一名干员装两件源石溶剂，攻击力和只装一件一样。原因：装备的战斗效果按物品 id 建立 buff key（`item:<id>:stat:…`、
`item:<id>:drain`），同一 id 的第二份装上时用同一个 key，`addBuff` 默认整条替换，于是第二份顶掉了第一份；卸下任意一份，剩下那份的加成也一起没了。
对局里能同时戴上的是两件进阶（两件普通入手即合成），普通加进阶是两个 id，本来就叠加。锤的特殊效果和 M3茧甲的复活次数一直按份数计，只有属性条和
持续效果不叠，规则本身不一致。

**改动** [ASSUMED]（物品原文和黑板都没有「同名装备不可叠加」）：同一干员身上同一物品的第二份及以后各用自己的 key（`item:<id>#n`），每份都计算；
第一份的 key 不变，借出的仍是 `item:<id>@lend`（同一件再借只刷新）。两件进阶源石溶剂：攻击力 +60%+60%，每秒流失 120 生命；两件进阶维式重锤：+25%+25%。

测试：`test/content/items.test.js`（两件进阶源石溶剂 / 普通 + 进阶 / 一件；两件进阶维式重锤——前者在旧代码上失败，攻击 800 而不是 1100）。golden 不变
（剧本里每件装备只有一件）。

### 37.52 缇缇二技能「封护」：生命比例相同时锁最后部署的干员（#906，GitHub PR #907，@DoveK0908，round58）

玩家报告（#906）：我方干员全部满血时，「封护」总是锁开局最先部署的那名。原因：选人按生命比例升序，平局时回落到创建序号（`a.id - b.id`），
等于永远偏向最早创建、也就是最先部署的干员。PRTS 的技能文本只写「选择一名攻击范围内的友方单位」，没有写平局规则。

**改动**（PR #907，维护者 2026-10-29 确认的口径）：生命比例最低者优先不变；比例相同时取 `deploySeq` 最大者——最后一次部署的干员（倒地后再部署、
【移动】都会刷新部署序号），再相同才回落到创建序号；与引星棘刺一技能「生命比例最低>最晚部署」的写法相同（`chess_char_5_15-thorn2.js`），候选仍只有
攻击范围内的干员（不含召唤物、装置）。只在开技能那一刻判定一次。注意：最终攻势的共用场地和联防按各自的部署顺序重新编号，第一期两个版本的部署
扫描顺序与第二期相反（自下而上），「最后部署」随之不同。

测试：`test/content/kits_alt_t5.test.js`（平局给后部署的那名、比例更低者仍优先；合入时补一组：先创建的干员原地【移动】一次后成为最后部署，
平局给它——把「最后部署」和「创建更晚」区分开）。golden：第二期上半 `roster-039` 变了（那场里缇缇二技能正好遇到平局），其他不变。

### 37.56 持续施法期间只停走路（#904，GitHub PR #905，@DoveK0908，round58）

**规则**：持续施法（`ab:channel`）只停住走路，不停别的：`ai.js updateEnemy` 从 buff 读出 `channeling` 并进 `standing`，与攻击前摇站住同级。
路线 WAIT（含传送门的等待）、DISAPPEAR / APPEAR、漏怪计时照常；恐惧立即把它带走（失衡时恐惧／诱导同样停住走路），运行中的诱导被停
[ASSUMED]。狂欢式演奏（`enemy_10034_cnvsax`）和死亡之眼（`enemy_1275_dwlock_2`）在整段施法里原地不动（0.3.3 及以前边施法边走）；结束条件：
技能自己的 `duration`、沉默、眩晕（`units.js` 把冻结／沉睡／浮空都置 `stun`）、锁定目标倒下或离场。结束时冷却重新开始计时（PRTS「同一技能的
冷却时间于该技能结束时开始计时」，[ASSUMED]），所以 10 s 冷却的狂欢式演奏跟在 10.5 s 施法之后、24 s 的死亡之眼跟在 8 s 施法之后，两次施法之间
照常走路。不用 `noMove`：它会把路线等待、传送门、漏怪和恐惧一起冻住（PR 第一版的做法，审查后改掉）；这两个 buff 只带 `disarm`。施法期间不移动
来自 #904 的官服录像，没有数据表字段 [ASSUMED]。

仍是简化的几点 [ASSUMED]：沉默／眩晕只在伤害拍上检查（狂欢式演奏每 0.5 秒、死亡之眼每 1 秒），两拍之间开始又结束的短暂沉默／眩晕不会打断

### 37.94 冻河二技能按维护者实测：持有者的技能或攻击范围内没有敌人时不触发（round63，Claude）

维护者 2026-11-03 在普通关卡实测冻河二技能：「干员技力一满并且技能/攻击范围内有敌人就自动放，没敌人不会放」。这和 §37.91 的读法一致
（期间去掉手动技能之间的 3 秒操作间隔，释放仍按持有者技能自己的条件，效果等持有者技能满足目标条件才触发）。只有一类以前不一致：持有者
技能的自动释放规则本身不要目标——技力满就放（SP_FULL）、受到伤害时放（TAKE_DAMAGE，重装等）、由干员自己的代码判断（NEVER，例如另一名
冻河的技能）——效果在技力满时就触发，周围没有敌人也一样（PRTS 备注写的是「不需要目标/满足目标条件」）。

**改动**（`server/sim/content/kits/ops/op-tocka.js enemyInReach`）：这些规则的持有者也要等它的攻击范围或技能自己的范围内有能攻击的敌人
（或它正阻挡着敌人）才触发效果；持有者开启技能时效果照常当场触发。影响最大的是重装：以前技力一满就把攻速加成用掉，敌人往往还没到；现在
等敌人进入攻击范围。治疗技能仍按范围内有受伤的友方判断（没有实测，保留推定）。

测试：`test/content/op_tocka.test.js` 加技力满就放的持有者；受击释放的持有者改为和其他规则一样先核对没有敌人、敌人在范围外都不触发，敌人
进入攻击范围后 0.2 秒内触发（这些持有者在旧代码下会提前触发，测试失败）。golden：只有 diy-136、diy-137 移动（场上有冻河，其余各族和
三个历史版本都没有她），首次后果都是另一名冻河持有二技能效果时等敌人进入她的攻击范围才触发：diy-136 从 64.2 秒推迟到 74.6 秒，diy-137
从 30.2 秒推迟到 30.57 秒。
