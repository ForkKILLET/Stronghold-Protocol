## 本分支：极光／忍冬特质升级（2026-11-11）

重新购买及精锐化又因副本更换清零。固定官方表 `6f63c14e` 的升级黑板应限制单次收益，n 控制每次升级所需触发数。
维护者确认本局同名干员共享进度；现按玩家＋原干员 baseId＋effectKey 使用已有 counters，不改变存储结构。
极光收益 1、2…12、12…，忍冬收益 1、1、2、2、3、3…；复制与投资人重复触发分别推进，出售和跨回合不清空。
商店、奖励、本人和侦察详情读取相同计数，保持只读及观察者隔离，回放沿用记录中的视图。
检查点可保留新计数，即使已卖光同名干员；旧版本已经销毁的副本触发历史无法追溯，不伪造完整迁移。
此修正替代下方最初文本适配时保留的升级假设，不改初雪及其它副本级计数。

验证：133 项定向／文档检查通过；三期 14 场完整 matches 与原基线逐字段相同，不修改 golden JSON。

## 本分支：“暴躁铁皮”装备与通讯机（2026-11-11）

官方固定数据 `6f63c14e` 的 charChessDataDict 给普通／精锐 `equipSlotNum: 4/6`，此前生成器遗漏，
服务端和界面均套用通用 2 格。现在保留非默认容量，并贯通棋子身份组合、配发、消耗品替换、AI、
临时指令及不变量检查；客户端拖放、替换确认及本人／队友详情使用同一容量算法，保留变形同构体规则。

163 项定向回归通过；现有含森蚺的三期 `coop4-FUNNY-6` 黄金摘要逐字段不变且错误为零，不更新基线。

通讯机沿用等级上限且只从普通池抽取，铁皮作为非商店特殊干员两处都不满足。用户补充这是铁皮的
特殊豁免，非通讯机全部候选取消等级限制。因此以 profile 标记明确豁免者，只有对该载体使用三期
通讯机时才把自身普通形态作为额外候选；其它普通候选、其它隐藏干员、寻呼模块和旧赛季不扩大。
候选保留原阶级，只有 maxTier 检查可被绕过，指定阶级仍严格匹配。本机回归验证普通／进阶通讯机
在Ⅱ级分别给 1／2 个铁皮副本，凑齐三只仍正常精锐化并返还装备；这些回归不替代官服规则证据。

2026-11-12 用户补充[官服视频 BV1FVWN6VEAr](https://www.bilibili.com/video/BV1FVWN6VEAr/?t=74)，
标题《以防你不知道2本的时候给“暴躁的铁皮”简易通讯器会发生什么》（总长 2:46）。已逐帧核对约
01:15–01:19：商店为Ⅱ级；普通简易通讯机说明显示获得 1 名第一盟约成员；目标为Ⅴ阶普通铁皮；
使用后通讯机消失，手牌区出现新的Ⅴ阶普通铁皮，原铁皮仍在场。因此“低等级通讯机可获得铁皮”
不再仅依玩家转述。录像没有验证进阶通讯机结果、混合候选权重或所有高阶普通干员；
混合权重仍沿用既有副本模型并标为 ASSUMED，不能据此扩大其它角色／效果的豁免。

### 37.11 Waiting-room ready feedback for every room member (PR #887, @YinqiMargatroid)

- **Reported (2026-10-25):** clicking 准备就绪 in a co-op waiting room is silent for both the sender and teammates;

  settings and browser unlock remain in effect. Cancelling and readying again retriggers the cue with no time-based
  cooldown. No new network frames, translations, game data or sim changes.
- **Evidence / [ASSUMED]:** this shared-room playback policy follows the reporter's request; no official multiplayer
  recording was independently checked. The sound itself reuses the existing briefing `g.infoReady` manifest key.
- **Regression coverage:** room-state subscription tests cover all listeners, repeat/cancel/re-ready, snapshots,
  reconnect restoration, AI/seat changes and match/solo exclusions. A real-server browser test checks shared playback
  and the briefing sound through actual decoded Web Audio sources.

### 37.48 同一名干员的两件相同装备都生效（#902，round58，Claude）

玩家报告（#902）：一名干员装两件源石溶剂，攻击力和只装一件一样。原因：装备的战斗效果按物品 id 建立 buff key（`item:<id>:stat:…`、
`item:<id>:drain`），同一 id 的第二份装上时用同一个 key，`addBuff` 默认整条替换，于是第二份顶掉了第一份；卸下任意一份，剩下那份的加成也一起没了。
对局里能同时戴上的是两件进阶（两件普通入手即合成），普通加进阶是两个 id，本来就叠加。锤的特殊效果和 M3茧甲的复活次数一直按份数计，只有属性条和
持续效果不叠，规则本身不一致。

**改动** [ASSUMED]（物品原文和黑板都没有「同名装备不可叠加」）：同一干员身上同一物品的第二份及以后各用自己的 key（`item:<id>#n`），每份都计算；
第一份的 key 不变，借出的仍是 `item:<id>@lend`（同一件再借只刷新）。两件进阶源石溶剂：攻击力 +60%+60%，每秒流失 120 生命；两件进阶维式重锤：+25%+25%。

测试：`test/content/items.test.js`（两件进阶源石溶剂 / 普通 + 进阶 / 一件；两件进阶维式重锤——前者在旧代码上失败，攻击 800 而不是 1100）。golden 不变
（剧本里每件装备只有一件）。

### 37.140 莱塔尼亚召唤触发、索敌与接敌移动

**问题与当前行为。** 旧实现仅在战斗开始时按成员生成召唤物，没有响应敌方单位被击倒。现按击倒事件生成一个小节；达到六名不同莱塔尼亚干员时，按盟约概率将这次召唤替换为一个乐部，而不是同时生成两种。六人档下，符合归属条件的我方干员被击倒时也会额外触发一次召唤，并按同一概率决定生成小节或乐部。常规档与六人档的存活上限分别为 10 和 20。召唤物归属盟约玩家，并在死者所在格中心生成。

两种召唤物使用显式战斗适配器，保留法术伤害、移动速度、阻挡数和对应攻击形状。它们是可与单位重叠的连续移动实体，不占用干员的 `_occ` 格槽；移动路径只绕开不可通行地形和障碍，按真实速度逐段接敌。小节在出生格已有可攻击目标时优先处理该格目标：可以攻击已由其他干员阻挡的敌人，但不会抢占其阻挡关系；对尚未被阻挡且处于接触范围的目标，仅在自身有正常阻挡容量时接手阻挡。局部候选为空后，小节切换为全局索敌且不再进入出生格优先模式。无本地候选的小节和所有乐部均直接使用全局索敌。无存活敌方单位时，每只召唤物独立锁存当时所在格中心并返回；新敌出现后恢复相应索敌行为。若只剩存活但不可选取的敌人，召唤物停留。
