# 局内记牌器与共享库存口径（2026-11-16）

用户要求查看高阶干员的剩余量和玩家分布，尤其是缪尔赛思。本次按**本服务器现有实现**提供只读工具，
不借新增 UI 修改库存规则，不将尚未复测的本服抽取机制说成官服实测。

## 库存账本

- [`SharedPool`](../../server/match/pool.js) 为未禁用、可自然出现的普通预设干员建立独立库存。
  容量来自 `GameData.poolCopies(id)`，包含按身份覆盖和多人倍率；多人翻倍一次，不随两人／四人再翻倍。
- 购买或直接获得时 `PlayerState.acquireChess` 默认 `fromPool:true`，通过 `poolCopies` 保存实际占用。
  普通通常一份，精锐通常三份；以该版本的 `goldenCopies` 为准。已显示的商店卡／奖励卡不预留，
  即使库存后来被买空仍可领取并形成超额占用；未来自然刷新跳过原始余量不大于零的条目。
- `requirePool:false` 仅绕过可获得性检查，**不表示零占用**。一般复制／免费获得仍会占池。
  真正不占池的路径包括显式 `fromPool:false` 和本来不属于共享池的身份。
  混合来源合成保留账本；普通获取触发合成或晋升可能补齐到精锐所需副本数。
- 出售／淘汰／暂存清理按同一实例保存的实际数量归还，不能按当前外观重新估算。
  内部余量可为负，工具的“卡池剩余”跟自然抽取一样最低为零，另列“超额占用”。

因此 UI 同时显示 `持有折算 = 初始数量 + 精锐数量 × goldenCopies`、`占池 = Σ poolCopies`，
并在有差额时列出“不占池”。持有统计作战区、整备区、整个暂存数组（包括当前看不到的溢出），
不含仅展示的商店／奖励卡。来源缺失显示未知，不把它当作免费副本。
卡池剩余直接读共享账本，不能用总量减外观折算值猜测。

### 缪尔赛思上限的证据范围（11 月 17 日复核）

当前两赛季生成数据均为六阶基础 5、多人成倍 2，缪尔赛思没有身份覆盖，故本服单人 5、多人共享 10。
这不是记牌器自行设置的容量。旧研究 `01-core-rules.md`／`06-multiplayer-ux.md` 中“缪尔赛思 4”
已被后续[主线 0.2.4 决定](../history/0.2.4.md#298-shared-inventory-466-430-approved-after-reviewing-the-source-video)
明确替代；该决定记录的来源为路标月报 #2，主线 #650 后续重申多人六阶 10。
但三期 profile 明确写明 `stock:null`、没有三期库存录像，当前容量是旧阶级默认值的沿用假设，
**不能据此断言三期官服的缪尔赛思也是 10**。未新增三期证据前不更改真实共享池，也不在 UI 单独显示另一个上限。

[PRTS 帮助](https://prts.wiki/w/卫戍协议/帮助)可支持三名普通合成精锐等基础玩法说明；
以上具体赠送占用、透支和抽取分母来自本服源码，不以该帮助页作为其官方证据。

## 自然刷出概率

沿用 [`SharedPool._eligible`](../../server/match/pool.js) 的候选集合：本次商店等级及以下、
剩余大于零的共享库存，加上**查询者自己的**满足商店门槛的自编库存。
其他玩家的私有自编库存不进入分母。以剩余副本加权，不另猜固定阶级权重。

目标剩余可抽份数为 `n`，候选总份数为 `N`：单栏概率 `p = n / N`（无候选时为零）。
自然干员栏位数为 `K = gd.shopSlots(level).chess`；展示不消耗库存，重复允许，
因此整次全新自然刷新至少一名为 `1 - (1 - p)^K`。
实现用 `-expm1(K * log1p(-p))`，避免极小概率被消减为零；正值小于显示精度时显示 `<0.001%`。
此值是自然刷新基准，不预言冻结保留、特殊指令／策略刷新或直接发放的结果。

## 界面与边界

选人采用调配式搜索／职业／等阶筛选，补盟约筛选及当前禁用标记，兼顾用户方案 a、b。
11 月 17 日按用户反馈抽取共用 `rosterFilters.js`，干员调配与记牌器共用搜索框／等阶按钮，职业筛选
同时复用到原自选入口，保持斜切按钮、职业图标、等阶颜色、输入行为和搜索样式一致。
记牌器的盟约改用信息页的 BondDisc，核心／附加两组在左侧平铺并独立滚动，干员列表在右侧。
置灰状态来自本局随机与模式固定排除，选中状态另用边框表示；置灰项仍可筛选以检查对应禁用干员。
短屏／窄屏可收起该列，选定后保留盟约名称并恢复结果列表宽度；全部盟约可清除选择，再点当前项也可清除。
不复用 HUD 盟约点击作为主入口，保留该处查看盟约的现有操作。
可选范围为本赛季可见预设干员，不混入隐藏身份、精锐重复项及自编条目。
收藏按 `charId` 跨赛季解析，默认只有 `char_249_mlyss`；固定入口和收藏只保存在本机。
显式取消全部收藏／固定不会被默认项覆盖。

小工具菜单与固定入口由同一注册表提供；默认固定作战统计，同一时刻只展开一个工具。
沿用作战统计的 modeless 角落定位，短屏不足 320 px 时记牌器在可见视口内展示，正文独立滚动。
选人复用现有 Modal，Escape 只关闭最上层，不连带关闭记牌器。

`g.cardCounter {chessId,seq}` 仅向请求者回传 `m.cardCounter`，不扩大 `m.public`，
不输出其他人的商店／奖励／私有自编条目。参与者（含已淘汰席位）可读；纯观战席仍沿用拒绝规则。
开启、连接且页面可见时每两秒查询，单请求在途，五秒超时；通过 matchKey／playerId／chessId／seq
拒绝旧回包。关闭／断线解绑；错误保留有标记的旧值，旧服务端不支持时停止自动重试。
使用现有 heavy bucket 限频；暂停期间可读，返回路径不触发动作、flush、重算、RNG 或回放记录。
版本／玩法插件 host 的帧白名单来自协议列表，独立 Match Worker 使用原回复通道。
没有增加账户／缓存／回放 schema；历史回放不显示实时库存工具。
