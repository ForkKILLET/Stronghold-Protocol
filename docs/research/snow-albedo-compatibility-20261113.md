# 雪地缺失表面的兼容排查（2026-11-13）

一位 Edge 玩家在雪地中看不到部分低地砖和整备台表面，冰块、山体和干员仍正常。
删除并重新下载资源、重启浏览器无效。玩家的 Edge 版本、GPU／ANGLE 后端尚待补充，当前没有在
其设备复现，因此下述为有资源证据支持的兼容候选，不能宣称已经确定驱动或浏览器根因。

## 已核实

两图的 `MT_icewild`、`MT_icewild_reflection` 共用 `TX_icewild_A`。材质是 opaque，未启用
alpha test／alpha blend；当前移植的场景 shader 不将该 albedo 的 alpha 用于 RGB 光照。
2048×2048 贴图中 1,814,547 个像素（43.26%）alpha=0，但 RGB 仍有有效颜色。例如
`(864,32)=(146,146,146,0)`，`(1056,32)=(140,144,147,0)`。
分别查看 RGB 与 alpha，零 alpha 区域对应灰色地砖和整备台，正 alpha 区域主要对应冰块与山体，
与玩家缺失表面的分布相符。其它三期主材质的沙地、地铁、教堂和炮台贴图没有全零 alpha 像素。

MAP9 几何检查未见非有限坐标或零法线；区块顶点索引也未越过自身格式边界。两张雪地场景没有
环境反射 cubemap，因此当前 renderer 不启用 PBS／法线／金属高光分支。现有资源加载使用
HTMLImageElement → Three.js Texture；Three.js 自有 canvas 直接显示，没有经过 Pixi 或 Canvas2D
再合成。资源完备检查不能证明浏览器解码或 GPU 上传结果正确。

候选原因是部分图像解码／上传路径丢失了 alpha=0 下的 RGB。
[WebGL 规范](https://registry.khronos.org/webgl/specs/latest/1.0/)规定了 HTMLImageElement 上传与
`UNPACK_PREMULTIPLY_ALPHA_WEBGL` 的关系；这只能作为排查依据，不能证明该玩家命中了某个实现缺陷。
仅把最终 fragment alpha 强制为 1 不能恢复之前已丢失的颜色。

## 兼容处理

导出器对无透明关键字、非水面、包含零 alpha 像素的 opaque albedo，从**已经编码的贴图**生成
`<name>_opaque_rgb.webp` 无损 RGB 副本，并让该材质的 `map` 引用副本。这样既消除无用 alpha，
又不改变此前光照拟合所用的 RGB。保留原 RGBA 文件和其清单身份；共用原贴图的 cutout、blend、
水面及独立法线／金属／自发光／光照数据不变。判断依据为材质属性，没有写死雪地图 ID。
旧运行时无需修改，继续读取标准 `scene.json` 的材质引用；没有扩大 ZIP 或缓存单文件上限。

本机安装仅改变上述两图的两个材质引用，新增一个 1,891,336 字节的共用 RGB 文件，其余八个
三期场景 JSON 与几何二进制保持逐字节一致。原贴图也保持原字节，解码后的 RGB 与新副本完全一致。
文件摘要及安装收据见 [JSON](snow-albedo-compatibility-20261113.json)。素材、清单、指纹和 ZIP
属于本机生成资源，不入 Git；本机资源版本不能直接当作线上最终合并版本。

## 验证与后续

CPU 回归覆盖零 alpha 下的有效颜色、原文件不被覆写、透明材质共享原图、多材质复用一份副本，
以及不含零 alpha 的贴图保持不变。实际雪地副本逐像素 RGB 相同，几何与光照参数未改。
资源清单、指纹与 ZIP 沿标准工具重建并核验。

最终定向检查 90 项通过，无失败或跳过，包含 Pillow 回归；改动 JS 的 ESLint 通过。

硬限额未触发，OOM 计数为零。详细本机日志在 `.state/snow-render-20261113/`。
