# Orange 协防零人数圆盘（2026-11-25）

[用户提供的回放](https://genshin.asm.ms:7999/?doctor=5JT4&replay=d6536263-699b-4d86-b003-662ae47ccdbf)，三期多人终极模拟，Orange#6383，定位 34:49（2,089,000ms，第 15 回合准备阶段）。

## 结论

该时刻服务器记录的协防为 `emptyShip: { count: 0, active: false, tier: 0, layers: 33 }`，没有被误计为一人或激活。这里的 33 是本服归档的内部 `layers` 字段，不代表官服三期协防存在可见或影响效果的层数。

圆盘留下来是因为通用显示筛选允许“有历史层数但没有成员”的盟约继续显示。协防的 `noStack: true` 表示效果不受层数影响，界面也不画层数，所以这条通用规则使它变成一个没有数字的灰图标。
半圈来自另一处独立问题：零人数仍选择人数进度素材，并用 `Math.max(1, filled)` 将 0 填充提升到一段。协防门槛为 2，最终取到 `2_1`；灰度／亮度滤镜只能使其变暗，不能清空那半圈。该处理起于本服 `c06d73f95`（2026-11-17，未激活人数进度），后续圆盘调整保留了这一逻辑。

## 层数语义与依据

协防、独行的效果固定，均不显示层数；三期官方数据的 `noStack: true` 且 `perStackParams` 为空，PRTS 三期的描述也没有按层数增长的效果。
本服内部 `addLayers` 仍接受 `noStack` 盟约，这是沿用旧期主线处理。[主线 #139 的维护者回复](https://github.com/sganggs/Stronghold-Protocol/issues/139#issuecomment-5996882974)解释独行的数值不随层数变化、助力仍使内部层数增加；旧研究表据此前置了隐藏计数的说明。
该旧期处理不能单独证明三期官服的隐藏计数行为。本次回放只证明本服写入了 33，不能将它直接称为官服正常的“历史层数”。
因此本轮修改的是显示资格：这种内部数值不能让零人、未激活的协防或独行出现在盟约栏。现有内部计数、总层数统计及游戏逻辑未作更改；是否调整三期模拟计数需另有依据。
