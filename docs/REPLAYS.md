# 账户对局回放

启用 `SP_USER_DB` 后，从新版开始的对局在服务端结束时自动入库。参与该局的真人玩家可以在博士档案的「对局记录」播放回放；观战者和其他账户不能读取。无需注册或另外登录，恢复档案后沿用同一份回放库。原有结算重看继续保留，不会因回放被淘汰而删除对局记录或统计。

## 内容与播放

- 记录完整经营过程：服务器确认后的刷新、购买、摆阵／朝向、装备、奖励、策略选择、就绪与暂停，以及对应的公共／私人状态变化。自动托管和 AI 的状态随服务端视图保存。聊天、恢复码、Cookie、内部用户 ID 不录入。
- 保存所有普通、联防、最终攻势和隐秘核心战场的原始 BattleSpec。战斗按该描述重新模拟显示，使用固定 1/30 秒逻辑帧；播放器倍速只改变播放时钟，不改变游戏规则。领袖共享血量同步和服务器确定的结束时间随回放保留。
- 支持播放／暂停、0.5／1／2／4／8 倍速、时间轴、上／下一步操作、按回合跳转，以及切换玩家和该回合战场。准备期可查看商店、手牌／临时区、阵容和装备。
- 回放使用独立的渲染器和模拟实例，不占玩家席位、不发送游戏／战斗上报、不写本机对局统计，也不重放聊天或语音。正式对局中可以浏览档案，需结束当前对局后再播放回放。

这不是视频或旧引擎副本：**战斗重模拟要求同一内容规则身份 `cs`**。原版规则身份变化后仍能查看已记录的经营过程，战斗区会明确提示版本变化，不使用新版规则冒充旧战斗。插件回放需要服务器仍提供该内容集，并遵循原有脚本同意／Worker 隔离规则；内容不可用时保留经营记录。历史回放、同版本运行态恢复和跨版本引擎归档是不同的能力。

## 保存与固定

公开回放需要档案的「允许公开回放」开启，并且本人保存的该条回放已设为公开。`POST /api/user/replay/share` 接受 `{matchId,shared}`；`GET /api/doctors/<公开编号>/replay?matchId=<id>` 可匿名读取。公开状态保存在玩家与对局的关系上，不改变同局其他参与者的设置。总开关关闭后旧链接不再提供正文，重新打开仍保留逐条选择；撤回不能收回观看者已下载的副本。

对外正文在存储 Worker 内派生、压缩，仅保留分享者的经营视角和操作，战斗仍含所有战场；队友私有状态／操作不会下发。玩家当局昵称、阵容、公共选择与战斗仍可见。私有原文不改、不另存新格式；公开投影附加可用经营视角名单，播放器据此限制选择。公开历史和公开回放分别授权：允许回放不自动开放完整对局记录。

公开不等于固定，仍使用原保存／淘汰额度；淘汰时公开授权随本人保存关系一起删除。其他玩家仍保留同局正文，也不会让已被本人淘汰的公开链接重新有效。

本人对局记录继续并列播放／固定，更多操作内设置公开／私密并复制链接；总开关关闭时明确提示未生效，并提供「公开设置」入口。公开档案提供独立回放列表，即使对局记录不公开也可列出逐条允许的回放；观看页没有固定、修改公开状态等所有者操作。经营视角只允许分享者，战场仍可切换；不发送游戏命令。

默认每个账户保留 **10** 个回放，最多固定 **9** 个。新回放进入时，按结束时间淘汰最旧的未固定回放；最后一个未固定名额用于持续接收新局。固定状态属于各自账户，其他玩家取消固定或淘汰同一局不会影响自己的记录。同一场多人对局在磁盘只保存一份压缩内容，最后一个账户不再保留它时才回收正文。

操作放在记录表格的「回放」列：播放、固定／取消固定。固定不会打开结算；点击记录其他位置仍查看原结算，详情中也提供播放入口。表头和回合数保持左对齐。离线档案缓存不作为回放正文存储，也不能离线修改固定状态；失效或已被其他设备淘汰的入口会给出错误提示。

## 服务器配置

统一配置文件（[SERVER_CONFIG.md](SERVER_CONFIG.md)）新增：

```json
{
  "replays": { "perUser": 10, "maxBytes": 8388608 }
}
```

- `perUser`：0–100。`0` 停止新录制，并在启动时回收未固定回放；不删除结算。固定上限始终是 `max(0, perUser - 1)`。
- `maxBytes`：单局未压缩记录上限，64 KiB–64 MiB，默认 8 MiB；另有 100000 条事件的硬上限。超出时放弃该局录制，正常对局和结算继续，不保存截断回放。降低它不会删除已存正文。
- 环境变量 `SP_REPLAY_LIMIT`／`SP_REPLAY_MAX_BYTES` 和启动参数 `replayLimit`／`replayMaxBytes` 按原有优先级覆盖文件，重启生效。
- 降低数量限制不会自动取消固定。现有固定数超过新固定上限时，启动拒绝该配置；先在旧设置下取消固定，再降低上限。只读配置检查工具校验文件，账户中的固定数量由存储启动时核对。

未配置账户库时不录制。资源、模型、字体继续走原有加载／预载流程；回放不会复制素材到 SQLite 或资源 ZIP。

## 存储与恢复

`server/replays/capture.js` 记录视图差量，复用 `shared/stateDelta.js` 的补丁格式。录制缓冲随现有 Match 检查点保存；同版本重启继续录制并扣除停服间隔。结算 outbox 携带回放，SQLite 事务一起提交；按局去重，重试不会使已淘汰的回放重新出现。主线程、完整 Match Worker、插件 Host 走同一结束回调；最后一名玩家离开时等待异步结束，再释放房间。

正文在账户存储 Worker 内压缩，HTTP 直接发送已压缩字节；不在游戏主线程重新压缩。新增 `replays`／`user_replays` 表及独立 `replay_schema` 版本 1，不改变原账户表或其 `PRAGMA user_version=1`。旧服务可以忽略附加表，回滚不需要删掉用户账户；SQLite 一致备份包含回放和固定关系。

新增私有同源 HTTP：

| 方法 | 路径 | 内容 |
| --- | --- | --- |
| GET | `/api/user/replay?matchId=<id>` | 仅本人保留的参与对局；无缓存，支持 gzip |
| POST | `/api/user/replay/pin` | `{matchId, pinned: true/false}`，事务校验归属与固定上限 |

统计接口的记录增加可选 `replay` 元数据，顶层 `replays` 给出保存数／固定数与上限；列表不携带正文。没有上传或任意删除回放的公开接口。

## 验证

`test/users/replays.test.js` 覆盖限额、独立固定、淘汰、重启、降低限制保护、正文预算与差量时间轴。`test/replays-integration.test.js` 覆盖真实 Match 操作、检查点接续、本机／Worker 结算、私有 API、同源校验和插件 IPC 正文隔离。

`SP_E2E=1 node --test test/ui/account-replays.e2e.test.js` 使用独立无头 Chrome／Firefox、本地真实录制与 SQLite 服务，验证经营／战斗、暂停、回退、切换、固定与移动布局并截图。`SP_E2E_BUILD=1` 使用生产构建。截图位于忽略目录 `test/e2e/out/account-replays/`；测试不操作玩家的浏览器或生产房间。
